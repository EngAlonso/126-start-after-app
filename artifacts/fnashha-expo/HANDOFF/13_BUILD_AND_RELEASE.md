## Development Server (Expo Metro)

### Start the Dev Server

```bash
# From the monorepo root
pnpm --filter @workspace/fnashha-expo run dev

# Or from the artifact directory
cd artifacts/fnashha-expo
npx expo start
```

The Replit workflow `artifacts/fnashha-expo: expo` runs this automatically. In Replit, the Expo dev server is accessible via the Expo Go app or the built-in preview for Expo Web.

### Environment for Dev Server

The API base URL is read from `app.config.js` → `extra.origin` which is populated from `process.env.API_BASE_URL`. In the Replit environment the API server runs at the artifact path `/api` on the shared dev domain — no additional env setup is needed for local dev.

---

## Environment Variables

| Variable | Purpose | Required For |
|---|---|---|
| `EXPO_PUBLIC_API_BASE_URL` | Backend API base URL for production builds | Production APK/IPA |
| `API_BASE_URL` | Dev server API URL (read into `app.config.js`) | Local dev |

Resolved at runtime by `hooks/api-base.ts` → `apiUrl(path)`.

## Expo Go (Quick Device Preview)

1. Install **Expo Go** on iOS or Android.
2. Start the dev server (`npx expo start`).
3. Scan the QR code shown in the terminal.

Expo Go does not require any build toolchain — it runs the JS bundle directly. This is the fastest way to preview on a real device.

## Expo Web Preview

```bash
npx expo start --web
```

Expo Web runs in the browser as a React Native Web app. RTL must be explicit (`direction: 'rtl'`) in each screen — `I18nManager` is a no-op on web.

## EAS Build (Cloud Build — Recommended)

The project is configured with **EAS Build** (`eas.json` at the project root). EAS handles the native build on Expo's cloud infrastructure — no local Android SDK or Xcode required.

### Prerequisite
```bash
npm install -g eas-cli
eas login
```

### Build Commands

```bash
# Android APK (for direct install / testing)
eas build --platform android --profile preview

# Android AAB (for Play Store)
eas build --platform android --profile production

# iOS IPA (requires Apple account)
eas build --platform ios --profile production
```

### Build Profiles (`eas.json`)

| Profile | Purpose | Output |
|---|---|---|
| `development` | Debug build with dev client | APK / IPA |
| `preview` | Release build for internal testing | APK / IPA |
| `production` | Store-ready build | AAB / IPA |

## Local Android APK Build

> ⚠️ **Environment Warning:** A local APK build requires the Android SDK, Java (JDK 17+), Gradle, and `adb` to be present. These are **not available by default in the Replit workspace**. Use EAS Build (above) instead.

If you have a local environment with the full Android toolchain:

```bash
cd artifacts/fnashha-expo
npx expo run:android
```

Verify the toolchain before attempting:
```bash
java -version         # must be JDK 17+
adb version           # Android Debug Bridge
```

## Firebase / Push Notification Files

| File | Platform | Required For |
|---|---|---|
| `google-services.json` | Android | FCM push notifications |
| `GoogleService-Info.plist` | iOS | APNs push notifications |

These files must be present at the project root before building. They are gitignored — obtain them from Firebase Console → Project Settings.

For iOS push, the following must also be set server-side (API env vars):
- `APNS_KEY_ID`
- `APNS_TEAM_ID`
- `APNS_KEY_PATH` (or `APNS_KEY_P8`)

## OTA Updates (Expo Updates)

The app is configured for Expo OTA updates. JS-only changes can be pushed without a full App Store / Play Store release:

```bash
eas update --branch production --message "Fix: chat send bug"
```

Native changes (new permissions, new native modules, `app.json` config) require a full rebuild and store submission.

## App Icons and Splash Screen

Source assets are in `assets/`:
- `icon.png` — base app icon (1024×1024)
- `adaptive-icon.png` — Android adaptive icon foreground
- `splash-icon.png` — splash screen image

All platform-specific icon sizes are auto-generated by Expo from `icon.png` during build.

- [ ] Verify RTL layout on web (Expo Web preview)
